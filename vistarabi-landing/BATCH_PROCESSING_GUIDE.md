# 🚀 VistaraBI Batch Processing Guide

This document provides instructions on how to use, extend, and maintain the VistaraBI Batch Processing Engine. The engine is designed to automate the ingestion of large numbers of datasets across multiple business domains and generate high-fidelity strategic reports.

## 📌 Overview

The batch processor simulates a full user journey:
1.  **Ingestion**: Reading files from `vistarabi-landing/datasets/{domain}/{archive}`.
2.  **Discovery (Module 4)**: Identifying computable KPIs based on data headers.
3.  **Analysis (Module 6)**: Generating a 10-turn AI diagnostic Q&A dialogue.
4.  **Strategy (Module 7/8)**: Simulating a 10-point strategic action plan and growth forecast.
5.  **Export (Module 9)**: Rendering professional PDF strategic reports.

---

## 🛠 Usage

### 1. Running a Batch Process
To run a full enterprise batch analysis across all configured domains:

```bash
cd vistarabi-landing
node batch_process_enterprise.mjs
```

*Note: If the PostgreSQL database is offline, the system utilizes a high-fidelity simulation to generate JSON and PDF artifacts.*

### 2. Generating PDFs
Once the JSON summaries are ready in `./batch_reports`, generate the Module 9 exports:

```bash
node generate_pdfs.js
```

## 📂 Adding New Domains

To add a new business domain (e.g., "Energy" or "Agriculture"):

1.  **Create the Directory**:
    Create a new folder in `vistarabi-landing/datasets/`.
    ```bash
    mkdir datasets/energy
    ```

2.  **Add Data**:
    Place data archives inside the new folder. Each archive should be a directory containing CSV or XLSX files.
    ```text
    datasets/energy/archive (1)/power_consumption.csv
    ```

3.  **Update the Script**:
    Edit `batch_process_enterprise.mjs` and add the new domain to the `DOMAINS` array:
    ```javascript
    const DOMAINS = [
        // ... existing domains
        { name: 'ENERGY', path: './datasets/energy' }
    ];
    ```

4.  **Add Mock Logic (Optional)**:
    If running in simulation mode, update `mockDiscoverKPIs`, `mockValidateStrategy`, and `mockAIInsights` in the script to provide domain-specific intelligence for the new domain.

## 🔧 Troubleshooting

### Database Connectivity
If you see a `PrismaClientInitializationError`, it means the PostgreSQL service is not reachable.
- Check service status: `Get-Service | Where-Object { $_.Name -like "*postgres*" }`
- Start service: `Start-Service -Name "postgresql-x64-18"` (requires Admin)
- If the DB cannot be started, the batch script will fall back to **Simulation Mode**, saving all data to `./batch_reports` as JSON.

### PDF Rendering Errors
If PDF generation fails, ensure you have run `npm install` to install `@react-pdf/renderer` and that the `@babel/register` configuration in `generate_pdfs.js` matches your local environment.
